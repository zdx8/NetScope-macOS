为什么好用

三件事，做扎实。

菜单栏三段直出

网络速率、CPU、内存各占一段，合成一项菜单栏空间。三段可独立开关， 点哪段弹哪段详情；数值按深浅色分别校准对比度，模板渲染跟随系统外观。

双页签，各管一摊

「清理释放」看 CPU / 内存占用大户，悬停进程行一键关闭； 「系统功能」看磁盘占用、本机速率与四档流量统计，一个面板不打转。

按应用聚合，口径干净

Chrome 的 Helper 归并成一条 Google Chrome（沿 proc_pidpath 找最外层 .app）； 开 TUN 型 VPN 时总量只认物理网卡去重，隧道内应用列表带盾牌标注。

怎么做的

不糊弄的三个细节。

01

数据从哪来

不引依赖，把系统自带的 nettop 接到伪终端上实时读：

nettop -P -x -L 0 -s 1 -J bytes_in,bytes_out -t external
  • -L N 的采样窗口固定 30 秒，与 N 无关——没法秒级，所以接 pty 自己读；
  • pty 让全缓冲变行缓冲，进程退出先 SIGTERM 再补 SIGKILL（实测 nettop 在 pty 下忽略 TERM）；
  • 输出是进程自启动以来的累计字节，速率靠两次采样差分。
02

告警怎么不吵人

  • 连续 3 次采样都超阈值才发通知——下载开始那一秒的峰值不会打扰你；
  • 同应用 10 分钟冷却，不连环轰炸；
  • 掉到阈值以下立即清零，下次从头计。
03

凭什么敢说轻

  • 主进程 CPU 0.06%、内存 32 MB（10 秒均值实测）；
  • 两个 nettop 子进程各 0.1%、6 MB；
  • 可执行文件 1 MB，装进菜单栏就安静待着。

安装

两条路，都一步到。

下载 DMG

  1. 从 这里 下载 NetScope-macOS-arm64.dmg（永久链接，始终最新版）
  2. 打开后把 NetScope 拖进「应用程序」，启动即可
  3. 首次启动若被 Gatekeeper 拦下：右键 →「打开」，或执行下面的命令
xattr -dr com.apple.quarantine /Applications/NetScope.app

包为临时签名（codesign --sign -），自用没问题；分发给别人请自行签名与公证。Release 附 .sha256 校验文件。

从源码构建

  1. 需要 Xcode 命令行工具（Swift 6.x），无需其他依赖
  2. 克隆后一条命令打包并启动
git clone https://github.com/zdx8/NetScope-macOS.git
cd NetScope-macOS
bash Scripts/build_app.sh

首次构建约 24 秒，增量 6–7 秒。产物在 dist/NetScope.app；另附 214 项自检与受控负载校准脚本。

已知限制

先说清楚，再用得放心。

  • 只统计 TCP / UDP socket。ICMP、部分 RAW socket 不计入，与「活动监视器」的数字不完全一致。
  • loopback 被排除。127.0.0.1 上的通信不显示。
  • 走 TUN 型 VPN 时，各应用之和会大于总量。VPN 客户端显示的是物理链路上的加密字节，与隧道内应用的明文互为副本——总量本身准确，但不能把各行相加。
  • 只跑 IPv6 的隧道识别不到。判据是 utun* 上有 IPv4 地址（macOS 会给每个 utun 都发 fe80::，用 IPv4 才能干净区分）。
  • 面板打开时菜单栏状态项会有系统高亮底。这是 NSPopover 锚定绘制的高亮层，按钮状态管不了。
  • CPU 温度与风扇转速显示不了。读 AppleSMC 需要特权助手，实测无特权时所有键都返回「不可读」——面板不放拿不到的数值，顶部留给磁盘占用与本机速率。
